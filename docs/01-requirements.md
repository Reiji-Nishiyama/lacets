# 01. 要件定義

## 1. 目的
日本からは行きにくい海外の名所（ラルプデュエズ等）や、目標イベント（富士ヒル等）のコースを、室内のスマートトレーナー上で「実際に走ったかのように」体験できるようにする。

## 2. 利用者と配布範囲
| フェーズ | 対象 | 配布方法 |
|---|---|---|
| 当面 | 開発者本人＋自転車仲間（Strava 有料会員、合計10名以内） | Web アプリの URL を共有 |
| 将来 | 一般配布 | 規約対応・Strava の審査を経てから判断 |

人数上限10名は Strava API の Standard Tier をレビューなしで使える上限に合わせたもの（`04-external-services.md` 参照）。

## 3. 動作環境
| 環境 | 形態 | サポート |
|---|---|---|
| Windows PC（仲間の多数派） | Chrome / Edge | 正式サポート。最優先で実機検証する |
| macOS | Chrome / Edge | 正式サポート（開発者の M4 MacBook Pro で検証） |
| iPad | 段階1: Bluefy（Web Bluetooth 対応ブラウザ）<br>段階2: Capacitor による iPad アプリ（TestFlight 配布） | サポート |
| Android | Chrome | ベストエフォート |
| Safari（macOS / iOS） | - | 非対応（Web Bluetooth 非対応のため） |

iPad では File System Access API が使えないため、動画は取り込み時にアプリ内ストレージ（OPFS / Capacitor Filesystem）へコピーする。ストレージ容量の警告を表示すること。

## 4. 機能要件

### F1. トレーナー接続
- F1-1 KICKR Core 2 に Bluetooth FTMS で接続できる
- F1-2 パワー・ケイデンスをリアルタイム表示できる
- F1-3 SIM モード（勾配・転がり抵抗・空気抵抗・風速）で負荷を制御できる
- F1-4 変速は自転車の実変速で行う（アプリ側の変速機能は持たない）
- F1-5 BLE 心拍計に接続できる（任意）
- F1-6 接続が切れたら自動再接続を試み、走行を一時停止する
- F1-7 開発・デモ用のシミュレータトレーナーを持つ

### F2. ルートの取り込み
- F2-1 GPX / TCX / FIT ファイルをドラッグ＆ドロップで取り込める
  - Strava のルート（手動エクスポート）
  - Garmin Connect のコース（手動エクスポート）
  - その他のサービスの GPX
- F2-2 Strava アカウントを連携し、自分のルート一覧から選んで取り込める
- F2-3 取り込んだルートは端末内に保存され、オフラインでも走れる
- F2-4 標高データを平滑化し、走行用の勾配プロファイルを生成する
- F2-5 勾配プロファイル・地図・総距離・獲得標高・最大勾配を事前に確認できる

### F3. 走行
- F3-1 ルート上の現在位置に応じた勾配をトレーナーに送る
- F3-2 パワーと物理モデルから速度を計算し、ルート上を進む
- F3-3 画面に、地図上の現在位置・勾配プロファイル・パワー・速度・ケイデンス・心拍・距離・経過時間・残り距離を表示する
- F3-4 勾配の再現度（トレーナー難易度）を 0〜100% で調整できる。既定値は 100%（実勾配の再現がコンセプトのため）
- F3-5 ライダー体重・バイク重量・ポジション（CdA プリセット）を設定できる
- F3-6 一時停止・再開・途中終了ができる

### F4. 記録と書き出し
- F4-1 走行を1秒ごとに記録する
- F4-2 FIT ファイルとして書き出せる（仮想ルートの GPS 座標付き）
- F4-3 Strava 連携時は走行をアップロードできる（「バーチャルライド」として）

### F5. 実走データとの比較（ゴースト）
- F5-1 Wahoo / Garmin のサイコンで記録した FIT ファイルを取り込める
- F5-2 実走 FIT からルートを生成して走れる（実走の気圧高度を使うため勾配精度が高い）
- F5-3 実走を「ゴースト」として表示し、同じ距離地点での時間差を表示する
- F5-4 走行後に、区間ごとのパワー・タイム比較レポートを表示する
- F5-5 比較の主指標はパワー（W, W/kg）とする（室内の速度は物理モデル依存のため）

### F6. 映像・画像
優先度: F6-5 → F6-2 → F6-3 → F6-1（走行動画は当面用意できないため最後）
- F6-1 自分で撮影した走行動画（MP4）を取り込み、走行位置と同期再生する
  - GoPro の埋め込み GPS、または同時に記録した FIT/GPX で位置合わせする
  - 再生速度はユーザーの仮想速度 ÷ 撮影時の速度で制御する
- F6-2 映像がない区間・ルートでは、Mapillary / Panoramax の画像を位置に応じて表示する
- F6-3 Google ストリートビューを表示できる（任意機能・API キー設定が必要）
- F6-4 画像のクレジットを表示する
- F6-5 3D 地形ビュー：地形と衛星画像の上で現在位置を追うカメラ表示。動画・路上画像がなくても全ルートで使える

## 5. 非機能要件
- N1 勾配指令の更新は 1 Hz 以上、パワー表示の遅延は 1 秒未満
- N2 2時間以上の連続走行でメモリリーク・処理落ちがないこと
- N3 ユーザーデータ（ルート・走行・FIT）は端末内に保存し、サーバーに保存しない
- N4 ネット接続がなくても、取り込み済みルートを走れる（地図・画像は除く）
- N5 走行中にブラウザがスリープしない（Screen Wake Lock API）

## 6. スコープ外
- Zwift Cog / Zwift Click / バーチャルシフト
- 3D の仮想世界
- 他ユーザーとの同時走行（マルチプレイヤー）
- ERG モードの構造化ワークアウト（将来検討）
